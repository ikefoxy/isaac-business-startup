# ByteBack employee playbook — submission checklist

Public assignment page: https://ikefoxy.github.io/isaac-business-startup/playbook.html

Professor access: open the link, enter an optional first name, click **Take my seat**, then choose **New-hire playbook**. Click the nine yellow roadmap markers. Expand each detail panel for exact commands and controls. **Kanban board** opens the interactive personal board; **Team feedback** opens four published GitHub issues. No GitHub account, password, downloads, or local server is required to view the assignment.

| Requirement | Where to find it | Specific evidence |
| --- | --- | --- |
| 1. Language selection | Stage 01 | HTML/CSS/JavaScript, Python standard library and SQLite; reasons and file map. |
| 2. IDE and setup | Stage 02 | Official VS Code download, Git/Python/Node links, extensions, exact clone/install/run commands, Windows instructions. |
| 3. Development strategy | Stage 03 | Kanban flow, one active task, daily updates, planning/demo cadence to confirm, definition of done. |
| 4. Git strategy and controls | Stage 04 | Branch names, commit example, PR template, independent review, squash merge, exact branch-protection setup. |
| 5. Issue tracking | Stage 05 + Kanban app | Interactive board, saved task status, real GitHub Issues link, owner and acceptance criteria. Local practice cards do not sync to GitHub. |
| 6. AI agents and controls | Stage 06 | GitHub Copilot, installation link, example prompt, private-data restrictions, human review and action limits. |
| 7. Code quality | Stage 07 | Pinned ESLint/Prettier/Ruff, real config files, activation command for pre-commit hook, CI, npm audit and CodeQL workflows. |
| 8. Testing frameworks | Stage 08 | Python unittest, exact test command, HTTP/temporary SQLite integration tests, regression and manual browser checks. |
| 9. Other tools and procedures | Stage 09 | Deployment/environment setup, secrets, backups/restoration, incident contact, shipping controls and publication. |

The playbook covers all nine required areas. Details stay expandable for readability; **Save as PDF** prints all nine stages and their details.

Repository branch protection is documented with activation steps and is not claimed to be enabled. A formal on-call rota and production hosting must be agreed before a live-service launch. GitHub Pages hosts the playbook and static storefront; it does not host the Python donation backend. These distinctions are stated in the guide.
