                              04 / GIT STRATEGY & CONTROLS
                              
Your code needs a plus-one.

                              

                                Experiment on your branch. Invite a teammate
                                before it joins main.
                              

                              
    
                                
  1. 
                                  1
                                  
    
                                    
    Claim a branch.
    
                                    
    
                                      Update main, then create
                                      feat/1-product-details. Use
                                      fix/ or
                                      docs/ for fixes or docs, with
                                      the actual issue number.
                                    
    
                                  
    
                                
    2. 
                                
  2. 
                                  2
                                  
    
                                    
    Leave breadcrumbs.
    
                                    
    
                                      Try
                                      feat(catalog): show battery
                                        health. Open a PR, link the issue, and show
                                      your tests and a screenshot.
                                    
    
                                  
    
                                
    3. 
                                
  3. 
                                  3
                                  
    
                                    
    Get a second pair of eyes.
    
                                    
    
                                      Ask Isaac or a teammate to review. Fix
                                      feedback, pass checks, squash merge,
                                      delete the branch. Keep direct pushes off
                                      main.
                                    
    
                                  
    
                                
    4. 
                              

                              

                                THE RULEThe person writing the code
                                doesn’t approve their own change.
                              

                            

                          

                          

                            
                              Branch commands & administrator controls
                              +
                            
                            

                              

                                
git switch main
git pull --ff-only
git switch -c feat/12-search
# Make your change and run the checks.
git add app.js app.css
git commit -m "feat(catalog): explain empty results"
git push -u origin feat/12-search

                                
                              

                              

                                Administrator: in
                                GitHub branch settings ↗, protect main: require a PR, one
                                approval, dismiss stale approvals, resolve
                                conversations, and require
                                quality and
                                tests checks with an up-to-date
                                branch. Block force pushes and deletion.
                                These remote settings still need
                                  activation.
                                If working alone, record that independent review
                                is unavailable.

                              06 / AI AGENTS & CONTROLS
                              
Meet your fast-thinking sidekick.

                              

                                AI can get you unstuck. You still hold the
                                steering wheel.
                              

                              
    
                                
  1. 
                                  1
                                  
    
                                    
    Give Copilot a small job.
    
                                    
    
                                      GitHub Copilot is the playbook’s approved
                                      coding assistant. Ask for an explanation,
                                      a draft or a test. Name the files and the
                                      finish line; use fictional data.
                                    
    
                                  
    
                                
    2. 
                                
  2. 
                                  2
                                  
    
                                    
    Keep your secrets secret.
    
                                    
    
                                      No donor details, database exports,
                                      passwords, keys or cookies in prompts. AI
                                      does not merge, deploy or buy postage on
                                      its own.
                                    
    
                                  
    
                                
    3. 
                                
  3. 
                                  3
                                  
    
                                    
    Read before you accept.
    
                                    
    
                                      Can you explain the code? Check security,
                                      sources and licenses. Run tests, disclose
                                      substantial AI help in the PR, and get
                                      human review.
                                    
    
                                  
    
                                
    4. 
                              

                              

                                REMEMBERAI can draft the work.
                                You’re responsible for what ships.
                              

                            

                          

                          

                            
                              Install the tool & try a good prompt
                              +
                            
                            

                              

                                Get the Copilot extension ↗. Example: “In app.js, make empty catalog
                                results clearer. Keep filtering and escaping
                                intact. Add a reset action, use demo data, avoid
                                new dependencies, and explain how to test on
                                mobile and desktop.”
                              

                              

                                Before accepting code, inspect authorization,
                                data access, escaping, and error states.
                                Read GitHub’s responsible-use guide ↗.
                              

                            

                          

                        

                        

                          

                            

                              07 / CODE QUALITY
                              
Catch the “oops” before launch.

                              

                                Let the tools find the boring mistakes. You get
                                to fix the interesting ones.
                              

                              
    
                                
  1. 
                                  1
                                  
    
                                    
    Give JavaScript a checkup.
    
                                    
    
                                      npm run check runs ESLint 10
                                      and Prettier 3. Formatting complaint? Run
                                      npm run format, then check
                                      again.
                                    
    
                                  
    
                                
    2. 
                                
  2. 
                                  2
                                  
    
                                    
    Let Ruff spot Python slips.
    
                                    
    
                                      Run
                                      .venv/bin/ruff check . for
                                      our selected correctness rules. Follow PEP
                                      8 when adding Python.
                                    
    
                                  
    
                                
    3. 
                                
  3. 
                                  3
                                  
    
                                    
    Check the locks, too.
    
                                    
    
                                      Run
                                      npm audit --audit-level=high.
                                      CodeQL workflows run security scans
                                      through GitHub Actions. Review alerts with
                                      Isaac before release.
                                    
    
                                  
    
                                
    4. 
                              

                              

                                BEFORE EVERY PRFix failing checks.
                                Review security alerts with Isaac before
                                release.
                              

                            

                          

                          

                            
                              Exact configs, commands & enforcement
                              +
                            
                            

                              

                                
npm run check
.venv/bin/ruff check .
npm audit --audit-level=high
# Fix formatting when needed:
npm run format

                                
                              

                              

                                eslint.config.mjs: strict equality,
                                no eval/debugger, duplicate keys, unreachable
                                code, and typeof checks. ruff.toml:
                                E9, F63, F7, F82. package.json:
                                pinned tools and formatting scope; legacy
                                storefront formatting and vendored QR code are
                                excluded.
                              

                              

                                .githooks/pre-commit runs npm
                                checks, Ruff, and integration tests after
                                git config core.hooksPath .githooks. It checks the working tree; stage your final
                                fixes. CI repeats checks, tests, and audits.
                                CodeQL scans on PRs, main pushes, and weekly
                                after publication. Windows: use
                                .venv/Scripts/ruff.exe. Enable
                                secret scanning and push protection in GitHub
                                where supported.
                              

                            

                          

                        

                        

                          

                            

                              08 / TESTING FRAMEWORKS
                              
Be the customer for five minutes.

                              

                                Happy path? Great. Now try the click nobody
                                planned for.
                              

                              
    
                                
  1. 
                                  1
                                  
    
                                    
    Start with the safety net.
    
                                    
    
                                      Run
                                      python3 -m unittest discover -s tests
                                        -v. Python unittest tests the real HTTP
                                      server with a temporary SQLite database.
                                    
    
                                  
    
                                
    2. 
                                
  2. 
                                  2
                                  
    
                                    
    Try to prove yourself wrong.
    
                                    
    
                                      Test both “it worked” and “it was
                                      rejected.” Fixing a bug? Add a test that
                                      catches it next time. Get every test green
                                      before merge.
                                    
    
                                  
    
                                
    3. 
                                
  3. 
                                  3
                                  
    
                                    
    Take the scenic route.
    
                                    
    
                                      Try donate → publish → reserve → collect →
                                      reward with fictional accounts. Check
                                      mobile, keyboard use and console errors.
                                      Put the results in your PR.
                                    
    
                                  
    
                                
    4. 
                              

                              

                                THE DEMO PATHDonate → publish →
                                reserve → collect → verify the donor reward.
                              

                            

                          

                          

                            
                              Your first test walkthrough +
                            
                            

                              

                                Use fictional donor@example.com and
                                student@example.com accounts.
                                Donate a laptop, sign in with the demo link, and
                                submit. Use Classroom demo controls to advance
                                through refurbishment and publish with sample
                                specs. Switch accounts, reserve, and simulate
                                collection. Return to the donor and confirm the
                                $20 reward. Also cancel a reservation and verify
                                restocking.
                              

                              

                                The automated suite covers authentication,
                                account isolation, CSRF/origin controls,
                                validation, competing reservations, pricing, and
                                rewards. Browser checks are manual; there is no
                                committed Playwright suite. Demo controls
                                simulate physical processing.
                              

                            

                          

                        

                        

                          

                            

                              09 / OTHER CONTROLS, TOOLS & PROCEDURES
                              
Good work. Now land it safely.

                              

                                A smooth launch needs protected data and a plan
                                for the unexpected.
                              

                              
    
                                
  1. 
                                  1
                                  
    
                                    
    Put the keys away.
    
                                    
    
                                      Local secrets go in ignored
                                      .env; live secrets go in
                                      protected host settings. Never commit
                                      donor data. Exposed key? Rotate it and
                                      tell Isaac.
                                    
    
                                  
    
                                
    2. 
                                
  2. 
                                  2
                                  
    
                                    
    Run the landing checklist.
    
                                    
    
                                      Pass checks, back up SQLite, stage behind
                                      HTTPS, and try sign-in, roles and
                                      receipts. Keep demo and live databases
                                      separate. Agree hosting with Isaac.
                                    
    
                                  
    
                                
    3. 
                                
  3. 
                                  3
                                  
    
                                    
    Know who to call.
    
                                    
    
                                      Something breaks? Pause the affected
                                      operation, contact Isaac in your agreed
                                      channel, and record sanitized errors.
                                      Restore carefully and write down the fix.
                                    
    
                                  
    
                                
    4. 
                              

                              

                                YOUR FIRST-DAY CHECKConfirm
                                repository access, your contact channel, and
                                your first issue with Isaac.
                              

                            

                          

                          

                            
                              Live setup, backups & publishing +
                            
                            

                              

                                Live configuration: copy
                                .env.example; set
                                BYTEBACK_MODE=live, HTTPS
                                PUBLIC_URL, separate
                                BYTEBACK_DB, SMTP settings,
                                ADMIN_EMAILS, and verified
                                DROPOFF_DESCRIPTION. The bundled
                                server is a pilot implementation; approve
                                hosting before launch.
                              

                              

                                Shipping: set
                                EASYPOST_API_KEY,
                                SHIP_TO_JSON, and
                                MAX_LABEL_USD. Test with an
                                EasyPost test key first. Only Isaac enables paid
                                labels; refunds/voids are handled outside the
                                app.
                              

                              

                                Recovery: schedule encrypted
                                daily SQLite backups via its backup API or CLI
                                .backup; restrict access and test
                                restoration. To roll back, pause writes and
                                restore approved code. Review database
                                compatibility and newer orders before restoring
                                data. There is no formal on-call rota yet;
                                define one before launch.
                              

                              

                                Assignment submission: publish
                                these files through your static host or GitHub
                                Pages (main / root), verify the public
                                /playbook.html URL while signed
                                out, and submit that link. Static hosting runs
                                this guide, not the Python backend.
